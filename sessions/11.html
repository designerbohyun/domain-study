    PART 1

    RDMA (Remote Direct Memory Access)

    먼저 서버 사이 통신의 방식부터 보겠습니다. 8회차에서 본 DMA를 서버 밖으로 넓힌 것이 RDMA입니다.

    1.1

    정의

    , Remote Direct Memory Access는 네트워크 카드가 상대 서버의 메모리에 직접 읽고 쓰는 통신 방식입니다. 운영체제 커널과 상대 CPU를 거치지 않아서 지연과 CPU 사용이 매우 낮습니다.

    핵심 특성은 세 가지입니다.

    • , 커널 우회: 앱이 커널을 거치지 않고 NIC에 직접 작업을 요청합니다.
    • Zero-copy, 복사 없음: 앱 메모리와 NIC 사이에 중간 복사가 없습니다.
    • CPU offload, CPU 부담 덜기: 패킷 처리와 재전송을 NIC 하드웨어가 합니다. 상대 CPU는 아예 끼어들지 않는 연산도 있습니다. 이걸 one-sided, 한쪽만 참여하는 연산이라고 합니다.
    Q. RDMA의 세 가지 핵심 특성은 무엇인가요?

    Kernel bypass, Zero-copy, CPU offload입니다. 커널을 거치지 않고, 중간 복사가 없고, 상대 CPU가 끼어들지 않습니다.

    1.2

    등장 배경

    • 1990년대 후반 HPC 클러스터에서는 TCP 통신을 처리하는 비용이 병목이었습니다. 이 수십 μs였고, 통신하는 동안 CPU가 묶였습니다.
    • 데이터가 앱에서 커널로, 커널에서 NIC으로 여러 번 복사되고, 패킷마다 CPU가 손을 댔기 때문입니다.
    "그럼 네트워크 카드가 상대 서버의 메모리에 직접 써 넣게 하자!"그래서 등장한 것이 바로 RDMA입니다.
    • 1999년부터 2000년 사이 InfiniBand 표준과 함께 RDMA 개념이 자리 잡았습니다. InfiniBand는 PART 2에서 봅니다.
    • 이후 Ethernet 위로도 넓어졌습니다. TCP 위의 , 그리고 PART 3에서 볼 RoCE입니다.
    • AI 분산 학습에서 GPU 한 장이 수백 Gb/s를 주고받게 되면서, RDMA는 사실상 필수 기술이 됐습니다.
    1.3

    구조

    1. RDMA의 구성 요소

    구성하는 일비고
    Verbs APIRDMA 프로그래밍 인터페이스libibverbs
    송신 큐와 수신 큐 한 쌍, 연결의 단위연결마다 하나
    Completion Queue, CQ작업이 끝났다고 알리는 큐앱이 폴링으로 확인
    Memory Region, MR미리 등록한 메모리, NIC은 여기만 접근키 lkey, rkey로 권한 관리
    • 메모리를 등록할 때 그 영역을 고정합니다. 이걸 pinning이라고 합니다. 8회차에서 DMA에 Pinned Memory가 필요했던 것과 같은 이유입니다.

    2. 연산의 종류

    • Send와 Recv: 양쪽이 모두 참여합니다. 받는 쪽이 미리 받을 자리를 마련해 둡니다.
    • RDMA Write와 RDMA Read: 한쪽만 참여합니다. 상대 CPU는 모릅니다.
    • Atomic: 상대 메모리의 값을 한 번에 읽고 바꿉니다.

    3. RDMA를 실어 나르는 망

    • InfiniBand: 처음부터 RDMA용으로 설계한 전용 망입니다. PART 2에서 봅니다.
    • RoCE v2: 일반 Ethernet과 IP 위에 RDMA 패킷을 UDP로 실어 보냅니다. 무손실 설정이 필요합니다. PART 3에서 봅니다.
    • iWARP: TCP 위의 RDMA입니다. AI 클러스터에서는 드뭅니다.
    1.4

    작동 방식

    먼저 두 방식의 경로를 나란히 보겠습니다.

    RDMA Write 한 번을 따라가 보겠습니다.

    1. 준비: 양쪽이 메모리 영역을 등록하고, QP를 만들어 서로 연결합니다.
    2. 요청: 보내는 쪽 앱이 "내 메모리 주소 X를 상대의 주소 Y에 써라"라는 작업 요청을 송신 큐에 넣습니다. 이 요청을 WR, Work Request라고 합니다.
    3. 전송: NIC이 메모리에서 데이터를 직접 읽어 패킷으로 만들어 보냅니다. 상대 NIC은 받은 데이터를 상대 메모리 주소 Y에 직접 씁니다.
    4. 완료: 끝나면 CQ에 완료 항목이 들어오고, 앱이 폴링으로 확인합니다.

    GPU 메모리를 메모리 영역으로 등록하면, NIC이 GPU 메모리와 네트워크 사이를 직접 오갑니다. 이것이 9회차에서 본 입니다. 8회차에서 본 BAR1 창이 이때 쓰입니다.

    Q. RDMA가 켜져 있지 않으면 학습이 아예 안 되나요?

    아닙니다. NCCL이 TCP 소켓으로 대신 보내서 동작은 합니다. 하지만 서버 사이 통신이 크게 느려집니다. NCCL 로그에 NET/Socket이 보이면 RDMA를 쓰지 않는 상태입니다.

    1.5

    이점

    • 지연이 짧습니다: TCP는 수십 μs, RDMA는 1에서 2μs 수준입니다. InfiniBand에서는 1μs 안팎입니다.
    • 을 끝까지 씁니다: 중간 복사가 없어서 링크 속도에 가깝게 보냅니다.
    • CPU가 계산에 집중합니다: 통신이 CPU를 거의 쓰지 않아서, 8회차에서 본 CPU 병목이 줄어듭니다.
    1.6

    부재 시 문제

    RDMA가 없다고 가정해 보면, 이런 문제가 생깁니다.

    • 서버 사이 가 TCP로 돌아갑니다. NCCL이 소켓 방식으로 떨어져 대역폭이 크게 줄고, 서버를 늘려도 학습 속도가 잘 늘지 않습니다. AllReduce는 10회차에서 봤습니다.
    • CPU가 패킷 처리에 묶여서, 데이터 전처리 같은 다른 일이 느려집니다.
    1.7

    단점

    • 프로그래밍과 설정이 복잡합니다: Verbs, 메모리 등록, 드라이버 묶음인 까지 맞춰야 합니다.
    • 메모리 등록에 비용이 듭니다: 등록하는 데 시간이 걸리고, 등록할 수 있는 양도 ulimit memlock으로 제한됩니다.
    • 패킷 손실에 아주 약합니다: Ethernet 위에서는 손실이 없는 망을 따로 구성해야 합니다. PART 3에서 봅니다.
    • 컨테이너에서 손이 갑니다: RDMA 장치를 컨테이너에 보여 주고, IPC_LOCK 권한을 줘야 합니다. 1.8에서 봅니다.
    1.8

    단점 극복을 위한 대안 기술

    1. UCX와 libfabric

    • 뜻: RDMA를 한 겹 감싸서 다루기 쉽게 만든 통신 프레임워크입니다. 이 대표입니다.
    • 해결하는 단점: Verbs를 직접 다루는 복잡함을 줄입니다.

    2. NCCL

    • 뜻: 사용자는 RDMA를 직접 다루지 않고, NCCL이 RDMA 연결과 전송을 맡습니다. 10회차에서 봤습니다.
    • 해결하는 단점: AI 학습에서 RDMA 프로그래밍 부담을 없앱니다.

    3. Kubernetes Network Operator

    • 뜻: NVIDIA Network Operator가 드라이버와 함께 SR-IOV 또는 RDMA Shared Device Plugin을 설치해, 컨테이너에 RDMA 장치를 자동으로 내줍니다. Device Plugin은 13회차에서 다룹니다.
    • 해결하는 단점: 컨테이너에서 장치를 보여 주고 권한을 주는 일을 자동화합니다.

    4. UEC의 UET

    • 뜻: 이 만든 Ethernet용 새 RDMA 전송 계층, Ultra Ethernet Transport입니다. 패킷 손실을 견디고 여러 경로를 함께 씁니다.
    • 해결하는 단점: 무손실 망에 기대는 약점을 풉니다. 1.10에서 봅니다.

    1.10

    최신 트렌드

    1. Ethernet용 새 RDMA 표준이 나왔습니다

    • 2025년 6월 11일 Ultra Ethernet Consortium이 사양 1.0을 공개했습니다. 9월에는 1.0.1로 다듬었습니다.
    • 앱에서 libfabric API를 거쳐 새 전송 계층 UET까지, 그리고 링크와 물리층 개선까지 한 묶음으로 정의합니다.
    • 쓰임새에 따라 AI Base, AI Full, HPC 세 가지 프로파일로 나눕니다.

    2. 손실을 견디는 RDMA 제품이 나옵니다

    • 2025년 10월 Broadcom은 UEC 사양을 따르는 800G NIC, Thor Ultra를 발표했습니다.
    • 패킷 단위로 여러 경로에 나눠 보내고, 순서가 바뀌어 도착해도 받아 주고, 잃어버린 패킷만 골라 다시 보냅니다. 무손실 망에 기대던 RoCE의 약점을 정면으로 겨냥한 기능입니다.
    꼭 알아 둘 것RDMA는 무손실 망을 전제로 하던 방식에서, 손실을 견디는 방식으로 넓어지고 있습니다.
    PART 2

    InfiniBand와 HCA (Host Channel Adapter)

    여기까지가 통신 방식, RDMA였습니다. 이제 그 RDMA를 처음부터 전제로 만든 망, InfiniBand로 넘어가겠습니다. InfiniBand에서 서버 쪽 카드를 부르는 이름인 HCA도 여기서 함께 봅니다.

    2.1

    정의

    는 처음부터 RDMA, 짧은 지연, 패킷 손실 없음을 목표로 설계한 고성능 전용 네트워크 표준입니다. 대형 AI와 HPC 클러스터에서 대표적으로 쓰는 망입니다.

    • 표준은 IBTA, InfiniBand Trade Association이 정합니다. 지금 장비는 사실상 NVIDIA, 예전의 Mellanox가 공급합니다.
    • 구성 요소는 서버 카드인 HCA, InfiniBand 스위치, 망 전체 경로를 관리하는 Subnet Manager, 그리고 케이블입니다.

    InfiniBand에서는 NIC을 HCA라고 부릅니다.

    • , Host Channel Adapter는 서버, 즉 Host 쪽 채널 어댑터라는 뜻입니다. 스토리지 같은 장치 쪽 어댑터는 TCA, Target Channel Adapter라고 부릅니다.
    • 실무에서는 같은 NVIDIA ConnectX 카드를 InfiniBand 모드로 쓰면 HCA, Ethernet 모드로 쓰면 NIC이라고 부르는 경우가 많습니다. 포트마다 두 모드를 바꿀 수 있는 카드를 카드라고 합니다.
    • NCCL 환경 변수 NCCL_IB_HCA의 HCA는 RoCE NIC까지 포함한 RDMA 장치 전체를 가리킵니다.
    2.2

    등장 배경

    • 1999년 PCI 다음 세대의 I/O와 서버 연결 표준을 목표로 Intel, IBM 등이 연합했고, 2000년 1.0 사양이 나왔습니다.
    • 메인프레임의 채널 기반 I/O를 본떠 설계해서, 어댑터 이름도 Channel Adapter가 됐습니다.
    • 범용 I/O 표준으로는 자리 잡지 못했지만, 지연과 대역폭이 중요한 에서 살아남았습니다.
    "그럼 처음부터 RDMA와 무손실을 전제로 한 망을 따로 깔자!"그래서 등장한 것이 바로 InfiniBand입니다.
    • 2000년 InfiniBand 1.0 사양이 나왔습니다.
    • 2019년 NVIDIA가 Mellanox 인수를 발표했습니다. 인수 금액은 약 69억 달러입니다. 이후 InfiniBand는 NVIDIA AI 인프라의 핵심이 됐습니다.

    4. HCA 안쪽

    • 포트마다 두 가지 주소를 가집니다. Subnet Manager가 정해 주는 LID, 그리고 하드웨어마다 고유한 GUID입니다.

    Q. 서버에 mlx5 장치가 10개인데 NCCL에 다 쓰면 되나요?

    아닙니다. GPU 백엔드용 장치만 NCCL_IB_HCA로 지정해야 합니다. DGX H100이라면 GPU와 짝지은 8개입니다. 스토리지나 관리용 장치까지 섞이면 느린 경로로 트래픽이 가거나 상대 서버와 연결되지 않을 수 있습니다.

    2.4

    작동 방식

    1. 망 탐색: Subnet Manager가 망을 훑어 모든 포트에 를 주고 경로를 계산해 스위치에 배포합니다.
    2. 포트 활성화: HCA 포트는 Subnet Manager에 등록되어야 Active 상태가 됩니다. 그 전에는 Initializing입니다.
    3. 연결과 전송: HCA끼리 QP를 연결하고 데이터를 보냅니다. 1.4에서 본 RDMA 순서와 같습니다.
    4. 무손실 전달: 스위치는 다음 구간에 크레딧이 있을 때만 넘깁니다. 혼잡하면 기다릴 뿐 버리지 않습니다.
    5. 나눠 보내기: NCCL은 NCCL_IB_HCA로 지정된 HCA 포트들에 트래픽을 나눠 보냅니다.
    Q. InfiniBand가 패킷을 잃지 않는 이유는 무엇인가요?

    받는 쪽 버퍼에 여유, 즉 크레딧이 있을 때만 보내는 크레딧 기반 흐름 제어 때문입니다. 넘칠 상황이면 보내는 쪽이 기다립니다.

    Q. Subnet Manager가 죽으면 어떻게 되나요?

    이미 정해진 경로로 기존 통신은 계속됩니다. 하지만 링크가 바뀌거나 장애가 나면 경로를 다시 계산하지 못해 망이 복구되지 않습니다. 그래서 보통 Master와 Standby로 이중화해서 운영합니다.

    2.5

    이점

    • 지연이 가장 짧고 손실이 없습니다: 포트 사이 지연이 1μs 미만급이고, 실제로 쓸 수 있는 대역폭도 높습니다.
    • AI 집단 통신에 맞춘 기능이 있습니다: SHARP와 입니다.
    • 설치하면 바로 잘 됩니다: 성숙한 RDMA 환경이라 Ethernet의 RoCE보다 튜닝 부담이 적습니다.
    • HCA가 전송을 하드웨어로 처리합니다: CPU가 끼어들 일이 거의 없습니다.
    2.6

    부재 시 문제

    InfiniBand가 없다고 가정해 보면, 이런 문제가 생깁니다.

    • RoCE 망을 직접 무손실로 튜닝해야 합니다. 와 ECN 설정을 잘못하면 성능이 급락하거나 망이 멈출 수 있습니다. PART 3에서 봅니다.
    • 대형 학습 클러스터에서 지연, 특히 가장 늦게 끝나는 통신의 지연이 커져 확장 효율이 떨어집니다. 이걸 라고 합니다.
    • HCA가 없다면 서버는 InfiniBand 망에 아예 참여할 수 없습니다.
    2.7

    단점

    • 한 회사에 묶입니다: 스위치, 카드, 케이블, 관리 소프트웨어 대부분이 NVIDIA 제품입니다.
    • 비싸고 사람이 적습니다: 장비 비용이 높고, 운영해 본 인력이 Ethernet보다 적습니다.
    • 망을 두 벌 운영합니다: 기존 데이터센터 Ethernet 망, 보안, 관리 도구와 따로 운영해야 합니다.
    • InfiniBand만의 운영 지식이 필요합니다: LID, 파티션 키인 , Subnet Manager, 포트 상태를 알아야 하고, 펌웨어와 드라이버와 Subnet Manager의 버전 호환도 챙겨야 합니다.

    PART 3

    Ethernet과 RoCE (RDMA over Converged Ethernet)

    여기까지가 RDMA 전용 망, InfiniBand였습니다. 이제 데이터센터 어디에나 깔린 Ethernet 위에서 같은 RDMA를 돌리는 방법, RoCE로 넘어가겠습니다.

    3.1

    정의

    , RDMA over Converged Ethernet은 InfiniBand의 RDMA 전송 방식을 Ethernet 위에서 돌리는 기술입니다. 읽을 때는 "로키"라고 읽습니다. 표준은 InfiniBand와 같은 IBTA가 정합니다.

    • RoCE v1, 2010년: Ethernet 2계층 바로 위에 올립니다. 그래서 같은 서브넷 안에서만 동작합니다.
    • RoCE v2, 2014년: UDP와 IP 위에 올립니다. UDP 목적지 포트는 4791입니다. IP 라우팅이 되어서 지금의 표준입니다.

    바탕이 되는 은 IEEE 802.3 표준의 네트워크이고, 그 위에 IP, TCP, UDP를 얹어 씁니다. AI 클러스터에서 Ethernet은 두 가지 역할을 합니다.

    • 기본 역할: 관리망과 스토리지망입니다.
    • GPU 백엔드망: RoCE로 RDMA를 돌려 GPU끼리 통신합니다.
    Q. RoCE v1과 v2는 무엇이 다른가요?

    v1은 Ethernet 2계층에서만 동작해서 같은 서브넷 안에서만 씁니다. v2는 UDP와 IP 위에 실어서, 포트 4791을 쓰고 IP 라우팅으로 서브넷을 넘어갈 수 있습니다.

    3.2

    등장 배경

    • Ethernet은 1973년 제록스 PARC에서 시작해 1983년 IEEE 표준이 됐습니다. 이후 1G, 10G, 100G, 400G, 800G로 빨라지며 데이터센터 표준이 됐습니다.
    • InfiniBand의 RDMA 성능은 탐나지만, InfiniBand 망을 따로 깔고 운영하는 일은 부담이었습니다.
    • 데이터센터 Ethernet이 빨라지면서, 컴퓨팅과 스토리지를 하나의 망으로 합치려는 수요가 생겼습니다. 이걸 converged, 수렴된 망이라고 합니다.
    • AI 시대에는 들이 InfiniBand 종속과 비용을 피하려고 Ethernet 기반 AI 망을 택했습니다.
    "그럼 이미 깔린 Ethernet 위에서 InfiniBand의 RDMA를 그대로 돌리자!"그래서 등장한 것이 바로 RoCE입니다.
    • 2010년 RoCE v1이 나왔고, 2014년 IP 라우팅이 되는 RoCE v2가 나왔습니다.
    3.3

    구조

    1. 계층

    • RDMA Verbs와 InfiniBand 전송 계층은 그대로 둡니다.
    • 그 아래 링크 계층과 네트워크 계층만 Ethernet, IP, UDP로 바꿉니다.

    2. 무손실을 만드는 장치

    Ethernet은 원래 혼잡하면 패킷을 버리는 망입니다. RoCE를 쓰려면 손실이 없도록 따로 설정해야 합니다.

    구성하는 일비고
    PFC, Priority Flow Control특정 우선순위 트래픽에만 "잠깐 멈춤" 신호를 보내 버퍼 넘침을 막음최후의 수단
    과 혼잡하면 패킷에 표시하고, 보내는 NIC이 속도를 줄임혼잡 제어의 주력
    DSCPRoCE 트래픽을 전용 우선순위 큐로 분류스위치와 NIC 전체에서 같아야 함

    3. GID

    • RoCE의 주소는 IP를 바탕으로 한 입니다.
    • NCCL에서는 NCCL_IB_GID_INDEX로 올바른 GID를 골라야 합니다. 보통 RoCE v2와 IPv4 조합의 GID입니다.

    4. 속도와 스위치 칩

    • 포트 속도는 100G, 200G, 400G를 지나 지금 최신은 800G이고, 1.6T를 준비하고 있습니다.
    • 스위치 칩, 즉 ASIC은 Broadcom Tomahawk 5가 51.2Tb/s, Tomahawk 6가 102.4Tb/s입니다. NVIDIA는 Spectrum-4와 Spectrum-6를 만듭니다.
    • AI용 기능으로 PFC, ECN, 적응형 라우팅, 패킷 스프레이가 들어갑니다. 패킷 스프레이는 패킷을 여러 경로에 흩어 보내는 방식입니다.
    3.4

    작동 방식

    1. 일반 Ethernet의 전송

    • 기본은 최선 노력, 영어로 best effort 전송입니다. 혼잡하면 패킷을 버리고 TCP가 다시 보냅니다.
    • 서버 사이 트래픽은 같은 비용의 여러 경로에 나눠 보냅니다. 이걸 라고 합니다.
    • 다만 ECMP는 흐름 단위로 경로를 고르기 때문에, 큰 흐름 몇 개가 한 경로에 몰리는 문제가 있습니다. 큰 흐름을 elephant flow라고 부릅니다.

    2. RoCE 패킷 한 개의 여정

    1. 포장: NIC이 RDMA 패킷을 UDP와 IP로 감싸서 보냅니다.
    2. 분류: 스위치가 DSCP 값을 보고 무손실 큐에 넣습니다.
    3. 혼잡 표시: 버퍼가 차면 패킷에 ECN 표시를 합니다. 받는 NIC이 보내는 NIC에 혼잡 알림, CNP를 보내고, 보내는 NIC이 속도를 줄입니다.
    4. 잠깐 멈춤: 그래도 넘칠 것 같으면 PFC로 바로 앞 포트를 잠시 멈춥니다. 최후의 수단입니다.
    Q. RoCE 망을 무손실로 만드는 두 가지 핵심 기능은 무엇인가요?

    PFC, 우선순위 흐름 제어와 ECN, 혼잡 표시입니다. ECN 표시를 받아 보내는 속도를 줄이는 혼잡 제어 방식이 DCQCN입니다.

    Q. RoCE 환경에서 NCCL이 느릴 때 흔한 원인은 무엇인가요?

    잘못된 GID 인덱스로 RoCE v1이나 IPv6 GID를 고른 경우, PFC와 ECN이 빠졌거나 장비마다 다른 경우, NIC과 GPU가 서로 다른 NUMA 노드에 있는 경우, MTU가 맞지 않는 경우가 흔합니다. NUMA는 8회차에서 봤습니다.

    3.5

    이점

    • 있는 장비와 사람으로 를 씁니다: 기존 Ethernet 장비, 운영 인력, 도구, 보안 체계를 그대로 씁니다.
    • 여러 회사 제품을 고릅니다: 경쟁이 있어 비용이 낮고 공급이 안정적입니다.
    • InfiniBand에 가까운 성능이 납니다: 튜닝이 잘 됐을 때 지연과 대역폭이 InfiniBand에 근접합니다.
    • 크게 늘리기 쉽습니다: 수십만 엔드포인트 규모까지 확장하고, 컴퓨팅과 스토리지를 한 망으로 합칠 수 있습니다.
    • 실제 사례가 있습니다: Meta는 2024년 24,576 GPU 클러스터 두 개를 하나는 RoCE, 하나는 InfiniBand로 지었습니다. 둘 다 Llama 3 학습에 썼고, 가장 큰 모델은 RoCE 클러스터에서 학습했다고 밝혔습니다.
    3.6

    부재 시 문제

    RoCE가 없다고 가정해 보면, 이런 문제가 생깁니다.

    • Ethernet 망에서 RDMA를 쓸 수 없습니다. 학습 통신이 TCP로 돌아가 다중 서버 효율이 떨어지거나, 망을 따로 지어야 합니다.
    • 모든 AI 클러스터가 InfiniBand에 기대게 되어, 한 회사의 가격과 공급에 묶입니다.
    • 관리망, 스토리지망, 외부 서비스 연결에는 어차피 Ethernet이 필요하므로 망을 두 벌 운영하게 됩니다.
    3.7

    단점

    • 설정이 어렵습니다: PFC, ECN, DSCP, 버퍼 값이 스위치와 NIC 전체에서 일관돼야 합니다.
    • PFC가 부작용을 냅니다: 멈춤 신호가 연쇄로 퍼져 상관없는 트래픽까지 막히는 , 멈춤 신호가 폭주하는 PFC storm, 서로 기다리다 멈추는 교착 상태가 생길 수 있습니다.
    • 손실에 아주 약합니다: 하나를 잃으면 그 뒤를 모두 다시 보내는 Go-back-N 계열 방식이라, 손실이 조금만 나도 성능이 급락합니다.
    • 경로가 고르게 나뉘지 않습니다: 규모가 크면 ECMP 해시 충돌로 일부 링크만 혼잡해집니다. 집단 통신은 가장 느린 흐름이 전체 속도를 정하므로 꼬리 지연이 커집니다.
    • 지연이 조금 깁니다: 같은 속도라면 InfiniBand보다 지연이 다소 깁니다.
    3.8

    단점 극복을 위한 대안 기술

    1. NVIDIA Spectrum-X

    • 뜻: Spectrum 스위치와 이 함께 움직여 적응형 라우팅과 혼잡 제어를 하는 AI용 Ethernet 플랫폼입니다.
    • 해결하는 단점: RoCE 성능을 안정시키고 ECMP 해시 충돌을 줄입니다.

    2. UEC의 UET

    • 뜻: 손실을 견디고, 순서가 바뀌어도 받아 주고, 여러 경로를 함께 쓰는 새 전송 계층입니다. 1.10에서 봤습니다.
    • 해결하는 단점: PFC에 기대지 않아도 됩니다.

    3. Broadcom과 Arista 등의 AI Ethernet

    • 뜻: 스위치가 셀 단위로 트래픽을 나눠 보내는 스케줄드 패브릭, 로드 밸런싱 기능을 넣은 장비입니다.
    • 해결하는 단점: 경로 쏠림과 혼잡을 줄입니다.

    4. InfiniBand

    • 뜻: 튜닝 부담 없이 무손실 RDMA를 쓰는 전용 망입니다. PART 2에서 봤습니다.
    • 해결하는 단점: 무손실 설정 자체가 필요 없습니다.

    Q. 같은 400G라면 Ethernet과 InfiniBand의 성능이 같은가요?

    링크 속도는 같아도 혼잡할 때의 동작, 꼬리 지연, 집단 통신 가속 기능이 다릅니다. 그래서 실제 학습 성능은 망 설계와 튜닝에 따라 차이가 납니다. nccl-tests 같은 측정 도구로 직접 비교합니다.

    꼭 알아 둘 것RoCE는 Ethernet 위의 RDMA이고, 성패는 무손실 설정에 달려 있습니다. 설정이 잘되면 InfiniBand에 가깝고, 잘못되면 망 전체가 느려지거나 멈춥니다.
    3.10

    최신 트렌드

    1. AI 백엔드망에서 Ethernet이 InfiniBand를 앞섰습니다

    • 시장 조사 회사 Dell'Oro는 2025년이 전환점이었다고 밝혔습니다. AI 백엔드망에서 Ethernet이 InfiniBand를 앞섰다는 것입니다.
    • 2025년 4분기와 2025년 한 해 모두, AI 클러스터용 데이터센터 스위치 매출의 3분의 2 이상이 Ethernet이었습니다.
    • 불과 2년 전에는 InfiniBand가 80% 가까이를 차지했습니다.

    2. 스위치 칩 한 개가 102.4Tb/s가 됐습니다

    • 2025년 6월 Broadcom은 102.4Tb/s 스위치 칩 Tomahawk 6를 출하하기 시작했습니다. 200G 포트 512개, 또는 100G 포트 1,024개를 만들 수 있고, 사양을 지원합니다.
    • NVIDIA의 Spectrum-6 기반 Spectrum-X Photonics도 CPO 방식입니다. SN6810은 102.4Tb/s, SN6800은 칩 네 개로 409.6Tb/s입니다. 2026년 생산과 출하가 시작됐다는 보도가 있고, 서버 제조사를 통한 공급은 2026년 하반기로 알려졌습니다.

    3. 데이터센터 여러 곳을 하나로 잇습니다

    • 2025년 8월 NVIDIA는 Spectrum-XGS를 발표했습니다. 거리에 맞춰 혼잡 제어를 조정해, 떨어진 데이터센터 여러 곳을 하나의 AI 클러스터처럼 묶는 기술입니다.
    • NVIDIA는 이것을 scale-up, scale-out에 이은 scale-across라고 불렀습니다.
    꼭 알아 둘 것AI 서버 간 통신의 주류가 Ethernet으로 옮겨 가고 있고, 그 중심에는 RoCE와 그 뒤를 잇는 Ultra Ethernet이 있습니다.
    PART 4

    NIC (Network Interface Card)

    여기까지가 망의 종류였습니다. 마지막으로, 어느 망을 쓰든 서버에 꽂혀 실제로 통신을 수행하는 카드, NIC으로 넘어가겠습니다.

    4.1

    정의

    , Network Interface Card는 서버를 네트워크에 연결하는 카드입니다. AI 클러스터에서는 RDMA, GPUDirect, 혼잡 제어까지 하드웨어로 처리하는 고성능 장치입니다.

    • 서버의 PCIe 슬롯에 꽂혀 Ethernet이나 InfiniBand 링크를 제공합니다. InfiniBand 모드로 쓸 때 부르는 이름이 PART 2에서 본 HCA입니다.
    • 역할에 따라 네 단계로 발전했습니다. 일반 NIC, 일부 처리를 맡는 , 자체 CPU 코어를 단 DPU, 그리고 AI GPU 통신 전용의 SuperNIC입니다. DPU의 대표는 NVIDIA BlueField입니다.
    4.2

    등장 배경

    • 네트워크 속도가 CPU의 패킷 처리 속도를 앞지르면서, 처리를 NIC으로 내려보내는 방향으로 발전했습니다. 이걸 라고 합니다.
    • AI 클러스터에서는 GPU 한 장이 400Gb/s 이상을 주고받아야 해서, NIC 하나를 여러 GPU가 나눠 쓰면 바로 병목이 됐습니다.
    "그럼 GPU마다 전용 NIC을 붙이고, 통신 처리는 NIC이 다 하자!"그래서 등장한 것이 바로 GPU마다 RDMA NIC을 하나씩 짝지은 구조입니다.
    • DGX H100은 H100 8장에 ConnectX-7을 8개, GPU마다 하나씩 붙입니다.
    • 인프라 처리까지 맡는 DPU, AI 통신에 특화한 SuperNIC이 그 뒤를 이었습니다.
    4.3

    구조

    1. 구성

    구성하는 일수치와 비고
    PCIe 인터페이스서버의 CPU, 메모리, GPU와 연결Gen5 x16, 7회차
    네트워크 포트케이블이나 광모듈을 꽂는 자리QSFP, OSFP 규격
    패킷 처리 엔진체크섬, 분할과 합치기, 여러 큐로 나누기TSO, LRO, RSS
    RDMA 엔진QP와 CQ 처리, 메모리 직접 읽고 쓰기PART 1
    • : 물리 NIC 하나를 여러 개의 가상 기능, VF로 나눠 VM이나 Pod에 직접 내줍니다.
    • 이 밖에 암호화 같은 기능도 NIC이 맡습니다.

    2. DGX H100의 NIC 배치

    • GPU 백엔드용 ConnectX-7 8개가 GPU마다 하나씩 붙고, 각각 포트당 400Gb/s입니다.
    • 스토리지와 관리용으로 BlueField-3 DPU 2개가 따로 있습니다.
    • 400Gb/s는 초당 50GB입니다. PCIe Gen5 x16은 한 방향 약 64GB/s라서, NIC 하나가 PCIe 한 슬롯에 들어갑니다. 7회차에서 본 숫자입니다.
    Q. 서버에 NIC이 왜 GPU 수만큼 필요한가요?

    GPU 한 장이 다른 서버와 주고받는 데이터가 수백 Gb/s라서, NIC을 함께 쓰면 바로 병목이 됩니다. GPU마다 가까운 NIC을 하나씩 짝지으면 통신이 서로 간섭하지 않고, PCIe 경로도 짧아집니다.

    4.4

    작동 방식

    1. 준비: 드라이버가 메모리에 송신과 수신용 링 버퍼를 만듭니다.
    2. 송신: CPU나 GPU가 보낼 데이터의 위치를 적은 디스크립터를 씁니다. NIC이 로 데이터를 읽어 보냅니다.
    3. 수신: NIC이 받은 데이터를 DMA로 메모리에 쓰고, 인터럽트나 폴링으로 알립니다.
    4. RDMA 모드: Verbs 작업 요청을 NIC이 직접 처리합니다. 1.4에서 본 순서입니다.

    어느 단계든 데이터를 옮기는 것은 8회차에서 본 DMA입니다.

    4.5

    이점

    • CPU 부담이 줄어듭니다: 패킷 처리와 전송을 NIC이 맡습니다.
    • 은 넓고 지연은 짧습니다: GPU마다 포트당 400Gb/s를 씁니다.
    • GPU마다 독립된 통신 경로가 생깁니다: GPU와 NIC을 짝지어 배치하면 경로가 서로 겹치지 않습니다. 같은 번호 GPU의 NIC끼리 묶는 레일 구성은 12회차에서 다룹니다.
    4.6

    부재 시 문제

    고성능 NIC이 없다고 가정해 보면, 이런 문제가 생깁니다.

    • 서버 사이 통신 대역폭이 모자라 다중 서버 학습을 넓힐 수 없습니다.
    • CPU가 네트워크 처리에 쓰여 데이터 로딩과 전처리가 늦어집니다.
    4.7

    단점

    • 비용과 전력이 큽니다: 고성능 NIC과 광모듈 모두 값이 비싸고 전력을 많이 씁니다.
    • 버전 관리가 필요합니다: NIC 펌웨어, OFED 드라이버, 커널이 서로 맞아야 합니다.
    • 배치를 잘못하면 성능이 반으로 줄어듭니다: NIC과 GPU가 다른 PCIe 스위치나 다른 노드에 있으면 느려집니다. 8회차에서 봤습니다.
    4.8

    단점 극복을 위한 대안 기술

    1. DPU

    • 뜻: BlueField처럼 NIC 위에 CPU 코어를 올려, 스토리지, 보안, 가상 네트워크 처리를 NIC 위에서 합니다. 이런 카드를 라고 합니다.
    • 해결하는 단점: 서버 CPU를 풀어 주고, 여러 사용자를 나눠 격리하는 멀티테넌시를 하드웨어로 지킵니다.

    2. SuperNIC

    • 뜻: ConnectX-8, ConnectX-9 SuperNIC처럼 GPU 통신 전용으로 만든 NIC입니다. 적응형 라우팅과 혼잡 제어를 하드웨어로 돕습니다.
    • 해결하는 단점: Ethernet에서 RoCE 성능이 흔들리는 문제를 줄입니다.

    3. CPO

    • 뜻: Co-Packaged Optics, 광 변환을 스위치 칩 바로 옆에서 처리합니다.
    • 해결하는 단점: 따로 꽂는 광모듈의 전력을 줄입니다.

    4.10

    최신 트렌드

    1. GPU당 네트워크 대역폭이 1.6Tb/s로 커집니다

    • ConnectX-8 은 800Gb/s 세대입니다. Broadcom Thor Ultra와 함께 800G RDMA NIC을 대표합니다.
    • 2025년 10월 NVIDIA는 ConnectX-9 SuperNIC을 발표했습니다. Rubin GPU 한 장에 최대 1.6Tb/s를 제공하고, 포트 하나는 최대 800Gb/s입니다. GPU 한 장 기준으로 DGX H100의 400Gb/s보다 네 배 넓습니다. 2026년 Vera Rubin 플랫폼과 함께 나옵니다.

    2. DPU가 더 큰 CPU를 품습니다

    • 같은 때 NVIDIA는 BlueField-4를 발표했습니다. Grace CPU와 ConnectX-9를 한 장에 묶어, 네트워크 대역폭은 800Gb/s로 BlueField-3의 두 배입니다.
    • 계산 성능은 BlueField-3의 6배라고 밝혔고, 2026년 Vera Rubin 플랫폼에서 초기 공급을 시작합니다.

    3. Ultra Ethernet NIC이 나옵니다

    • AMD는 UEC 사양을 지원하는 400G NIC, Pensando Pollara 400을 출하하고 있습니다. 800G 후속인 Vulcano는 PCIe Gen6 시스템용으로 2026년 출시를 예고했습니다.
    • Broadcom Thor Ultra도 UEC 사양을 따르는 800G NIC입니다. 1.10에서 봤습니다.
    꼭 알아 둘 것NIC은 GPU 통신 전용 SuperNIC과 인프라 처리 전용 DPU로 역할이 갈라지며, 세대마다 대역폭이 두 배씩 커지고 있습니다.
