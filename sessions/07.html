    7회차 · PCIe, Lane, Gen4·5·6, Host Memory

    지난 6회차에서는 메모리의 속도, 즉 대역폭과 지연을 봤습니다. 그리고 CPU 쪽 데이터를 GPU로 빠르게 보내는 방법으로 Pinned Memory를 봤습니다. 오늘은 그 데이터가 실제로 지나가는 길, CPU와 GPU 사이의 연결 안으로 들어가 보겠습니다.

    CPU와 GPU는 라는 표준 연결로 이어집니다. PCIe는 , 우리말로 레인이라는 기본 길을 여러 개 묶어 씁니다. 그리고 세대가 하나 오를 때마다 레인 하나의 속도가 두 배가 됩니다. 이 길의 CPU 쪽 끝에 있는 메모리가 입니다.

    PART 1

    PCIe (Peripheral Component Interconnect Express)

    먼저 CPU와 GPU를 잇는 길 자체, PCIe부터 보겠습니다.

    1.1

    정의

    는 CPU와 GPU, NIC, SSD 같은 장치를 잇는 표준 고속 직렬 연결입니다.

    • 장치와 장치를 일대일로 잇습니다. 이걸 점대점, 영어로 point-to-point 연결이라고 합니다.
    • 데이터를 패킷 단위로 주고받습니다. 패킷은 데이터를 일정한 크기로 나눠 주소를 붙인 묶음입니다.
    • 규격은 업계 단체인 PCI-SIG가 정합니다.
    • GPU는 보통 x16, 즉 레인 16개짜리 슬롯에 연결됩니다. 레인은 PART 2에서 봅니다.
    1.2

    등장 배경

    • 1992년에 나온 PCI는 여러 장치가 선 하나를 함께 쓰는 병렬 버스였습니다. 한 번에 한 장치만 쓸 수 있었고, 최대 약 133MB/s였습니다.
    • 그래픽 카드가 이 속도에 막히자, 1997년 그래픽 전용 연결인 AGP가 따로 나왔습니다.
    • 장치마다 전용 연결을 만들다 보니, 표준이 여러 갈래로 나뉘었습니다.
    "그럼 모든 장치를 일대일 직렬 연결 하나의 표준으로 묶고, 필요한 만큼 넓혀 쓰자!"그래서 등장한 것이 바로 PCIe입니다.
    • 2003년 PCIe 1.0이 나왔습니다. 레인 하나가 2.5GT/s였습니다.
    • 그 뒤로 세대마다 레인 하나의 속도가 대략 두 배씩 올랐습니다. PART 3에서 봅니다.
    1.3

    구조

    1. 세 개의 층

    PCIe는 일을 세 층으로 나눠 맡습니다.

    층하는 일
    트랜잭션 층읽기와 쓰기 요청을 라는 패킷으로 만듭니다
    데이터 링크 층패킷에 순번과 오류 검사값을 붙이고, 잘못 받으면 다시 보냅니다
    물리 층패킷을 레인 위의 전기 신호로 바꿔 보냅니다

    2. 연결 모양

    구성하는 일예
    CPU 쪽 시작점. CPU와 Host Memory를 PCIe에 잇습니다CPU 안에 들어 있습니다
    길 하나를 여러 장치로 나눕니다GPU 서버의 PCIe 스위치 칩
    Endpoint맨 끝에 붙는 장치입니다GPU, NIC, NVMe SSD

    3. 서버 GPU의 두 가지 형태

    • PCIe 카드형: 일반 슬롯에 꽂는 형태입니다.
    • 모듈형: 보드에 직접 올리는 형태입니다. GPU끼리는 NVLink로 잇지만, CPU와는 여전히 PCIe로 잇습니다.
    Q. PCIe 카드형 GPU와 SXM GPU는 무엇이 다른가요?

    PCIe 카드형은 GPU끼리도 주로 PCIe나 브리지로 통신합니다. SXM은 NVSwitch를 거쳐 GPU끼리 NVLink로 빠르게 통신하고, 전력 한도도 높습니다. H100 기준으로 PCIe 카드형은 350W, SXM은 700W입니다. 그래서 대규모 학습에는 SXM이 유리합니다.

    1.4

    작동 방식

    코드에서 cudaMemcpy를 부르면 어떤 일이 생기는지 따라가 보겠습니다.

    1. 명령 보내기: CPU가 드라이버를 통해 GPU에 "어디서 어디로 몇 바이트"를 적어 보냅니다. GPU의 레지스터를 CPU 메모리 주소처럼 읽고 쓰는 방식이고, 이걸 라고 합니다. 이 주소 창구가 BAR이고, 8회차에서 다룹니다.
    2. 직접 읽기: GPU의 복사 엔진이 PCIe를 거쳐 Host Memory를 직접 읽습니다. CPU가 한 바이트씩 옮기지 않습니다. 이 방식이 이고, 8회차에서 다룹니다.
    3. 패킷으로 오가기: 읽기 요청과 데이터는 TLP 패킷에 담겨, 세 층을 차례로 지나 레인 위를 오갑니다.
    4. VRAM에 쓰기: 도착한 데이터를 복사 엔진이 GPU의 VRAM에 씁니다.
    • 6회차 4.3에서 본 그림, 즉 Pinned Memory에서 DMA 한 번으로 GPU에 가는 길이 바로 이 경로입니다.
    • PCIe는 하위 호환이 됩니다. Gen5 GPU를 Gen4 슬롯에 꽂으면 Gen4 속도로 동작합니다.
    1.5

    이점

    • 어디에나 연결됩니다: 업계 표준이라 어떤 회사의 CPU와 장치도 서로 연결됩니다.
    • 빨라지면서도 호환됩니다: 1.0의 x16은 한 방향 약 4GB/s였고, Gen5의 x16은 약 64GB/s입니다. 16배가 되는 동안 하위 호환을 지켰습니다.
    • 넓게 늘릴 수 있습니다: 스위치로 GPU, NIC, SSD를 유연하게 붙입니다.
    1.6

    부재 시 문제

    PCIe 같은 표준이 없다고 가정해 보면, 이런 문제가 생깁니다.

    • 장치 회사마다 CPU와 잇는 전용 방식을 따로 만들어야 합니다. 같은 서버에 다른 회사 장치를 섞어 쓰기 어렵습니다.
    • NIC나 SSD가 GPU와 직접 주고받는 같은 기술도 만들기 어렵습니다. 모두 PCIe라는 같은 주소 체계 위에서 동작하기 때문입니다. GPUDirect는 9회차에서 다룹니다.
    1.7

    단점

    • GPU 안보다 훨씬 느립니다: Gen5 x16은 한 방향 약 64GB/s이고, H100의 는 3.35TB/s입니다. 약 50배 차이입니다.
    • GPU끼리 통신하기에도 좁습니다: 양방향 합으로 비교하면, H100의 NVLink 900GB/s는 Gen5 x16 약 128GB/s의 약 7배입니다.
    • 빨라질수록 신호가 약해집니다: 세대가 오르면 신호가 멀리 가지 못해, 신호를 다시 살리는 칩과 좋은 보드가 필요합니다. 비용이 오릅니다. PART 3에서 봅니다.
    Q. 50배 차이는 실제로 어느 정도인가요?

    예시 계산입니다. 6회차에서 본 7B 모델, FP16으로 14GB를 생각해 보겠습니다. HBM3에서 한 번 읽는 데는 약 4ms가 걸립니다. 같은 14GB를 PCIe Gen5 x16으로 보내면 약 0.22초가 걸립니다. 그래서 가중치는 한 번 GPU에 올리면 계속 VRAM에 두고 씁니다.

    1.8

    단점 극복을 위한 대안 기술

    1. NVLink와 NVSwitch

    • 뜻: GPU끼리 PCIe를 거치지 않고 잇는 NVIDIA 전용 연결입니다. 9회차에서 다룹니다.
    • 해결하는 단점: GPU끼리 통신하기에 좁다는 문제를 풉니다.

    2. NVLink-C2C

    • 뜻: NVIDIA CPU와 GPU를 칩 사이에서 직접 잇는 연결입니다. Grace는 900GB/s, Vera는 1.8TB/s입니다.
    • 해결하는 단점: CPU와 GPU 사이가 느리다는 문제를 풉니다. 대신 NVIDIA CPU에서만 씁니다.

    3. CXL

    • 뜻: 은 Compute Express Link의 줄임말입니다. PCIe의 물리 신호를 그대로 쓰면서, 장치끼리 같은 메모리를 일관되게 보는 기능, 즉 캐시 일관성을 더한 표준입니다.
    • 해결하는 단점: PCIe 너머의 메모리를 CPU 메모리처럼 붙여 쓰게 합니다. PART 4에서 다시 봅니다.

    4. UALink

    • 뜻: 여러 회사가 함께 만든 가속기끼리의 개방형 연결 표준입니다. NVLink에 대응하는 방향입니다.
    • 해결하는 단점: GPU끼리의 고속 연결을 한 회사 전용이 아닌 표준으로 쓰게 합니다.

    1.10

    최신 트렌드

    1. CPU와 GPU 사이가 PCIe를 떠나고 있습니다

    • 2026년 NVIDIA는 Vera CPU를 발표했습니다. GPU와 로 1.8TB/s로 묶여, GH200의 900GB/s보다 두 배입니다. 6회차 4.10에서 본 내용입니다.
    • NVIDIA는 이 속도가 PCIe Gen6의 약 7배라고 밝혔습니다.

    2. GPU끼리의 연결도 개방 표준이 나왔습니다

    • 2025년 4월 UALink 컨소시엄이 200G 1.0 규격을 공개했습니다. 레인 하나에 200GT/s이고, 가속기를 최대 1,024개까지 한 묶음으로 잇는 것이 목표입니다.
    • PCIe는 범용 연결로 남고, 성능이 중요한 GPU끼리와 CPU와 GPU 사이는 전용 연결로 옮겨 가는 흐름입니다.
    꼭 알아 둘 것PCIe는 사라지지 않지만, 가장 바쁜 길에서는 물러나고 있습니다. NIC, SSD, 일반 서버의 GPU처럼 여러 장치를 두루 잇는 일은 여전히 PCIe 몫입니다.
    PART 2

    Lane (레인)

    여기까지가 PCIe라는 길 전체였습니다. 이제 그 길을 이루는 기본 단위, 레인으로 넘어가겠습니다.

    2.1

    정의

    은 PCIe 연결의 기본 단위로, 보내는 신호선 한 쌍과 받는 신호선 한 쌍으로 이루어진 길입니다.

    • 신호선 한 쌍은 서로 반대인 신호를 함께 보내, 그 차이로 값을 읽습니다. 이걸 차동 신호라고 하고, 잡음에 강합니다.
    • 보내는 쌍과 받는 쌍이 따로 있어서, 보내기와 받기를 동시에 합니다. 이걸 full duplex, 즉 양방향 동시 전송이라고 합니다.
    • 레인을 몇 개 묶었는지를 링크 폭이라고 하고, x1, x4, x8, x16으로 씁니다.
    • Gen5 레인 하나는 한 방향 약 4GB/s입니다. 16개를 묶은 x16이 약 64GB/s입니다.
    2.2

    등장 배경

    • PCI 같은 병렬 버스는 선 수십 개로 비트를 동시에 보냈습니다.
    • 그런데 속도를 올리면, 선마다 신호가 도착하는 시간이 조금씩 어긋났습니다. 선이 많을수록 이 어긋남을 맞추기 어려웠습니다.
    "그럼 혼자서도 빠르게 달리는 직렬 길을 만들고, 필요한 만큼만 묶어 쓰자!"그래서 등장한 것이 바로 레인입니다.
    • 2003년 PCIe 1.0부터 레인을 묶어 폭을 정하는 방식을 썼습니다.
    • 레인끼리는 따로 동기를 맞추고, 받는 쪽이 다시 순서를 맞춥니다.
    2.3

    구조

    1. 링크 폭

    폭Gen5 한 방향 대역폭 (대략)주로 쓰는 장치
    x1약 4GB/s관리용 작은 장치
    x4약 16GB/sNVMe SSD
    x8약 32GB/s일부 NIC
    x16약 64GB/sGPU, 고속 NIC

    2. CPU가 가진 레인 수

    • CPU가 내어 줄 수 있는 레인 수는 정해져 있습니다.
    • AMD EPYC 9004는 소켓 하나에 Gen5 128레인, Intel Xeon Sapphire Rapids는 소켓 하나에 80레인입니다.

    3. 레인을 나누는 두 방법

    • PCIe 스위치: 위쪽 레인 묶음 하나를 아래쪽 여러 장치에 나눕니다. 위쪽 대역폭은 아래 장치들이 함께 씁니다.
    • , 우리말로 분기: x16 슬롯 하나를 x8 두 개, 또는 x4 네 개로 쪼개 씁니다.
    • 예를 들어 DGX H100은 GPU 8장과 ConnectX-7 NIC 8개를 PCIe 스위치 아래에 두고, GPU와 NIC를 하나씩 짝지어 배치합니다.
    2.4

    작동 방식

    1. 협상하기: 장치를 연결하면 양쪽이 몇 개의 레인을, 몇 세대 속도로 쓸지 정합니다. 이걸 , 영어로 link training이라고 합니다.
    2. 나눠 싣기: 보낼 데이터를 바이트 단위로 쪼개 여러 레인에 차례로 나눠 싣습니다. 이걸 striping이라고 합니다.
    3. 다시 맞추기: 받는 쪽은 레인마다 도착한 바이트를 원래 순서로 다시 붙입니다.
    4. 합산하기: 그래서 대역폭은 레인 수 곱하기 레인 하나의 속도입니다.

    일부 레인에 문제가 있으면, 협상 단계에서 더 좁은 폭으로 내려가 계속 동작합니다.

    2.5

    이점

    • 필요한 만큼만 씁니다: SSD는 x4, GPU는 x16처럼 장치에 맞는 폭을 고릅니다. 레인을 아낍니다.
    • 고장에도 버팁니다: 레인 일부가 안 되면 더 좁은 폭으로 계속 동작합니다.
    • 계산이 쉽습니다: 폭이 두 배면 대역폭도 두 배입니다. x8은 x16의 절반입니다.
    2.6

    부재 시 문제

    레인이 모자란다고 가정해 보면, 이런 문제가 생깁니다.

    • GPU 8장과 NIC 8개, NVMe SSD를 모두 x16으로 CPU에 직접 붙일 수 없습니다.
    • 그러면 스위치 위쪽 대역폭을 나눠 써야 해서, 데이터 로딩, 체크포인트 저장, 서버 사이 통신이 함께 느려집니다.
    2.7

    단점

    • CPU 레인 수가 한계입니다: 서버에 붙일 수 있는 장치의 수와 대역폭이 CPU 레인 수에 묶입니다.
    • 링크가 몰래 내려갑니다: 장착 불량, 라이저 카드, BIOS 설정 때문에 x16이 x8로, Gen5가 Gen3로 떨어질 수 있습니다. 그래도 시스템은 정상처럼 보여서 늦게 발견됩니다.
    • 스위치 위쪽을 나눠 씁니다: 스위치 아래 장치들이 동시에 바쁘면 서로 대역폭을 빼앗습니다.
    Q. x8로 떨어지면 성능이 절반이 되나요?

    CPU와 GPU 사이 대역폭이 절반이 됩니다. 학습 시간 대부분이 계산이면 체감이 작을 수 있습니다. 하지만 데이터 로딩, 체크포인트 저장, 서버 사이 GPUDirect RDMA 통신이 많은 작업은 크게 느려집니다. 그래서 특정 서버만 느리면 링크 폭과 세대부터 확인합니다.

    2.8

    단점 극복을 위한 대안 기술

    1. PCIe 스위치

    • 뜻: 레인 묶음 하나를 여러 장치로 나눠, 적은 CPU 레인으로 많은 장치를 붙입니다. 최근에는 ConnectX-8처럼 NIC 안에 스위치를 넣기도 합니다.
    • 해결하는 단점: CPU 레인 수의 한계를 넘깁니다.

    2. 듀얼 소켓 서버

    • 뜻: CPU를 두 개 꽂아 레인 수를 두 배로 늘립니다.
    • 해결하는 단점: 레인 부족을 풉니다. 대신 CPU마다 메모리와 장치가 나뉘는 문제가 생깁니다. 8회차에서 다룹니다.

    3. NVLink

    • 뜻: GPU끼리의 통신을 PCIe 레인에서 떼어 내 전용 연결로 보냅니다. 9회차에서 다룹니다.
    • 해결하는 단점: 스위치 위쪽을 GPU끼리 통신이 차지하는 문제를 줄입니다.
    2.9

    대안과의 비교

    구성GPU 하나가 쓰는 대역폭특징
    CPU에 직접 x16x16 전체를 혼자 씀가장 좋지만 CPU 레인을 많이 씀
    스위치를 거친 x16위쪽 대역폭을 나눠 씀GPU와 NIC를 같은 스위치에 두면 직접 통신에 유리
    x8 연결절반전송이 적은 추론 전용 서버에서 쓰기도 함
    꼭 알아 둘 것대역폭은 레인 수 곱하기 레인 하나의 속도입니다. 그래서 GPU가 x16으로, 제 세대 속도로 연결됐는지가 CPU와 GPU 사이 성능의 출발점입니다.
    2.10

    최신 트렌드

    1. NIC 안에 PCIe 스위치가 들어갑니다

    • NVIDIA ConnectX-8 SuperNIC은 PCIe Gen6 스위치를 안에 품고, Gen6 레인 48개를 씁니다. 2025년부터 HGX B300과 GB300 NVL72 시스템에 들어갔습니다.
    • GPU와 NIC 사이를 별도 스위치 칩 없이 이어, 서버 안의 레인 구성을 단순하게 만듭니다.
    • 2026년 ConnectX-9 자료에서도 호스트 연결은 PCIe Gen6 최대 48레인이고, 처리량은 최대 1.6Tb/s입니다.

    2. 레인 수는 그대로, 레인 속도가 오릅니다

    • 2026년 7월 AMD는 EPYC Venice를 출시했습니다. 레인은 128개로 EPYC 9004와 같지만, Gen5가 아닌 Gen6 레인입니다. 같은 레인 수로 대역폭이 두 배가 됩니다.
    꼭 알아 둘 것레인은 늘리기보다 빠르게 만드는 쪽으로 가고 있습니다. 그리고 그 레인을 어떻게 나눠 줄지가 서버 설계의 핵심이 됐습니다.
    PART 3

    PCIe 세대 (Gen4 · Gen5 · Gen6)

    여기까지가 레인 수, 즉 길의 폭이었습니다. 이제 레인 하나의 속도를 정하는 PCIe 세대로 넘어가겠습니다.

    3.1

    정의

    는 PCIe 규격의 버전으로, 세대가 하나 오를 때마다 레인 하나의 전송 속도가 약 두 배가 됩니다.

    • 속도는 , 즉 1초에 신호를 몇십억 번 보내는지로 씁니다. 실제 대역폭은 인코딩과 패킷 머리말 때문에 이보다 조금 낮습니다.
    • Gen4: 2017년 규격입니다. 16GT/s이고, x16 한 방향 약 32GB/s입니다.
    • Gen5: 2019년 규격입니다. 32GT/s이고, x16 한 방향 약 64GB/s입니다.
    • Gen6: 2022년 규격입니다. 64GT/s이고, x16 한 방향 약 128GB/s입니다.
    3.2

    등장 배경

    • GPU, NVMe SSD, 고속 NIC가 원하는 대역폭이 PCIe 속도를 계속 앞질렀습니다.
    • 특히 AI 서버의 NIC가 문제였습니다. 800Gb/s NIC는 1초에 약 100GB를 보냅니다. Gen5 x16의 한 방향 약 64GB/s로는 감당하지 못합니다.
    "그럼 레인 수는 그대로 두고, 레인 하나의 속도를 세대마다 두 배로 올리자!"그래서 등장한 것이 바로 세대별 PCIe 규격입니다.
    • 대략 3년에서 4년마다 새 세대 규격이 나왔습니다.
    • 2025년 6월에는 Gen7 규격도 나왔습니다. 3.10에서 봅니다.
    3.3

    구조

    1. 세대별 속도

    세대규격 연도레인 하나신호 방식x16 한 방향 (대략)대표 장치
    Gen320108GT/sNRZ, 128b/130b약 16GB/sV100 (PCIe), T4
    Gen4201716GT/sNRZ, 128b/130b약 32GB/sA100
    Gen5201932GT/sNRZ, 128b/130b약 64GB/sH100, B200
    Gen6202264GT/sPAM4, FLIT, FEC약 128GB/sConnectX-8, B300
    Gen72025128GT/sPAM4, FLIT, FEC약 256GB/s아직 제품 없음

    2. Gen6에서 바뀐 신호 방식

    • NRZ: Gen5까지 쓴 방식입니다. 신호 한 번에 0과 1, 즉 1비트를 보냅니다.
    • : Gen6부터 쓰는 방식입니다. 전압을 네 단계로 나눠 신호 한 번에 2비트를 보냅니다. 같은 주파수로 두 배를 보냅니다.
    • : 전방 오류 정정입니다. 네 단계 전압은 구분이 어려워 오류가 늘기 때문에, 받는 쪽이 오류를 바로 고치도록 여분 정보를 붙입니다.
    • : 패킷을 고정된 크기로 묶어 보냅니다. FEC를 붙이기 쉽고, 처리도 단순해집니다.
    3.4

    작동 방식

    1. 최고 세대로 맞추기: 연결할 때 양쪽이 지원하는 세대 중 가장 높은 쪽으로 맞춥니다. 장치가 Gen5여도 서버가 Gen4면 Gen4로 동작합니다.
    2. 신호 다시 살리기: 세대가 높을수록 신호가 멀리 못 갑니다. 그래서 보드 배선이 길면 중간에 라는 칩을 넣어 신호를 다시 만듭니다.
    3. 쉴 때는 낮추기: 일이 없을 때는 전력을 아끼려고 링크 속도를 낮췄다가, 전송이 시작되면 다시 올립니다.
    Q. 쉬고 있는 GPU의 PCIe 세대가 Gen1로 보이는데 고장인가요?

    대개 고장이 아닙니다. 쉬는 동안 전력을 아끼려고 속도를 낮춘 것입니다. 부하를 준 상태에서 다시 봤을 때 최대 세대와 같아지면 정상입니다.

    3.5

    이점

    • 같은 레인으로 두 배를 보냅니다: 레인 부족 문제가 그만큼 줄어듭니다.
    • 빠른 NIC를 제대로 씁니다: NIC 속도를 바이트로 바꾸면 짝이 보입니다. 200Gb/s는 약 25GB/s로 Gen4 x16 안에, 400Gb/s는 약 50GB/s로 Gen5 x16 안에, 800Gb/s는 약 100GB/s로 Gen6 x16 안에 들어갑니다.
    • 그래서 GPU 세대와 NIC 속도, PCIe 세대가 함께 올라갑니다. A100은 Gen4와 ConnectX-6 200Gb/s, H100은 Gen5와 ConnectX-7 400Gb/s, B300은 Gen6와 ConnectX-8 800Gb/s가 짝입니다.
    3.6

    부재 시 문제

    세대가 낮은 서버를 쓴다고 가정해 보면, 이런 문제가 생깁니다.

    • Gen5 GPU를 Gen4 서버에 꽂으면, CPU와 GPU 사이 대역폭이 절반이 됩니다.
    • 데이터 로딩, 오프로딩, 를 내리고 올리는 일이 모두 느려집니다. KV 캐시는 PART 4에서 봅니다.
    • 빠른 NIC가 PCIe에 막혀, 서버 사이 통신이 제 속도를 내지 못합니다.
    3.7

    단점

    • 비싸집니다: 세대가 오를수록 보드, 케이블, 리타이머 비용과 전력이 늘어납니다.
    • 도입이 늦습니다: CPU와 메인보드가 함께 지원해야 의미가 있어서, 장치보다 늦게 퍼집니다. Gen6 장치는 2025년에 나왔지만, Gen6 서버 CPU는 2026년에 나왔습니다. 3.10에서 봅니다.
    • 그래도 GPU 안보다 느립니다: Gen6 x16 한 방향 약 128GB/s도, HBM3 3.35TB/s의 약 26분의 1입니다.
    3.8

    단점 극복을 위한 대안 기술

    1. CXL

    • 뜻: PCIe의 같은 세대 물리 신호 위에 메모리 일관성 기능을 얹은 표준입니다.
    • 해결하는 단점: 새 연결을 따로 깔지 않고 PCIe 세대 향상을 그대로 메모리 확장에 씁니다.

    2. NVLink와 NVLink-C2C

    • 뜻: PCIe 세대가 오르기를 기다리지 않는 전용 고속 연결입니다.
    • 해결하는 단점: 세대 향상 속도가 느리다는 문제를 우회합니다.

    3. CPO

    • 뜻: 는 Co-Packaged Optics의 줄임말로, 칩 바로 옆에 광 부품을 붙여 빛으로 보내는 방식입니다. 네트워크 스위치에서 먼저 쓰기 시작했습니다.
    • 해결하는 단점: 전기 신호가 멀리 못 가는 문제를 풉니다.
    3.9

    대안과의 비교

    항목Gen4Gen5Gen6
    x16 한 방향약 32GB/s약 64GB/s약 128GB/s
    신호 방식NRZNRZPAM4, FLIT, FEC
    맞는 NIC200Gb/s급400Gb/s급800Gb/s급
    대표 서버A100 세대H100, B200 세대B300 세대
    꼭 알아 둘 것장치와 서버 중 낮은 쪽 세대로 동작합니다. 그래서 GPU 세대만큼 서버 플랫폼의 PCIe 세대도 함께 봐야 합니다.
    3.10

    최신 트렌드

    1. Gen6가 실제 서버에 들어왔습니다

    • 2025년 NVIDIA ConnectX-8이 Gen6로 HGX B300과 GB300 NVL72 시스템에 들어갔습니다. 2.10에서 본 내용입니다.
    • 2026년 7월 AMD EPYC Venice가 Gen6를 지원하는 첫 서버 CPU로 나왔습니다. 다만 전체 제품군은 2027년에 걸쳐 나온다는 보도가 있습니다.

    2. Gen7은 나왔고, Gen8은 준비 중입니다

    • 2025년 6월 PCI-SIG는 PCIe 7.0 규격을 공개했습니다. 레인 하나 128GT/s이고, x16 양방향 합 최대 512GB/s입니다.
    • 2025년 8월에는 PCIe 8.0을 발표했습니다. 256GT/s, x16 양방향 합 1TB/s가 목표이고, 2028년까지 회원사에 규격을 내는 계획입니다.
    • 다만 Tom's Hardware는 PCI-SIG 회장이 256GT/s 목표를 아직 탐색 단계라고 조심스럽게 말했다고 보도했습니다.
    꼭 알아 둘 것규격은 3년마다 두 배씩 앞서 가지만, 서버에 퍼지는 데는 몇 년이 더 걸립니다. 2026년 현재 GPU 서버의 주력은 Gen5이고, Gen6가 막 들어오는 중입니다.
    PART 4

    Host Memory (호스트 메모리)

    여기까지가 CPU와 GPU를 잇는 길이었습니다. 마지막으로 그 길의 CPU 쪽 끝에 있는 메모리, Host Memory를 보겠습니다.

    4.1

    정의

    는 CPU에 연결된 시스템 메모리로, GPU로 보낼 데이터가 출발하고 GPU에서 나온 결과가 도착하는 곳입니다.

    • CUDA에서는 CPU를 Host, GPU를 Device라고 부릅니다.
    • 보통 DDR4나 DDR5 메모리이고, Grace와 Vera 같은 NVIDIA CPU는 LPDDR5X를 씁니다.
    • 6회차 4장에서 본 두 종류가 모두 Host Memory입니다. OS가 옮길 수 있는 Pageable과, 고정해 둔 입니다.
    4.2

    등장 배경

    • GPU는 자기 메모리, 즉 을 따로 가진 장치입니다. 입력 데이터는 Host Memory에서 받아 와야 합니다.
    • 그런데 모델이 VRAM보다 커지면서, VRAM에 다 담지 못하는 데이터가 생겼습니다.
    "그럼 VRAM에 다 안 들어가는 것은 크고 싼 CPU 쪽 메모리에 잠시 내려 두자!"그래서 Host Memory는 입력을 보내는 곳에서 VRAM 다음의 두 번째 저장 층으로 역할이 넓어졌습니다.
    • 옵티마이저 상태를 Host Memory로 내리는 ZeRO-Offload 같은 학습 기법이 나왔습니다.
    • 추론에서는 KV 캐시를 Host Memory로 내리는 기능이 추론 엔진에 들어갔습니다. 4.10에서 봅니다.
    4.3

    구조

    1. 메모리 채널

    CPU소켓 하나의 메모리 채널소켓 하나의 대역폭 (대략)
    Intel Xeon Sapphire RapidsDDR5 8채널약 307GB/s (DDR5-4800 기준)
    AMD EPYC 9004DDR5 12채널약 460GB/s (DDR5-4800 기준)
    • -4800 채널 하나는 약 38.4GB/s입니다. 8채널이면 약 307GB/s, 12채널이면 약 460GB/s입니다.

    2. 소켓마다 나뉜 메모리

    • CPU가 두 개인 서버는 메모리도 소켓별로 나뉩니다. 내 소켓 메모리는 가깝고, 옆 소켓 메모리는 멉니다. 이게 NUMA이고, 8회차에서 다룹니다.

    3. 서버 하나의 예

    • DGX H100은 GPU 8장의 VRAM이 모두 640GB이고, 시스템 메모리는 2TB입니다. Host Memory가 VRAM 합보다 세 배 넘게 큽니다.
    4.4

    작동 방식

    AI 작업에서 Host Memory가 하는 일을 순서대로 보겠습니다.

    1. 읽고 손질하기: 데이터셋을 디스크에서 읽어 전처리합니다. PyTorch의 DataLoader 워커들이 여기서 일합니다.
    2. Pinned 버퍼에 담기: 손질한 배치를 Pinned 버퍼에 담습니다. 6회차 4.4에서 본 pin_memory=True입니다.
    3. GPU로 보내기: GPU 복사 엔진이 PCIe로 읽어 갑니다. 그동안 GPU는 이전 배치를 계산합니다.
    4. 내려 두기: VRAM이 모자라면 옵티마이저 상태나 KV 캐시를 Host Memory로 내려 두고, 필요할 때 다시 올립니다. 이걸 이라고 합니다.
    5. 체크포인트 저장하기: GPU의 학습 상태를 Host Memory로 복사한 뒤 디스크에 씁니다.
    4.5

    이점

    • 크고 쌉니다: 서버 하나에 수백 GB에서 수 TB까지 둡니다. H100의 VRAM은 80GB입니다.
    • 늘릴 수 있습니다: 메모리 모듈, 즉 DIMM을 더 꽂아 늘립니다. HBM은 GPU 칩 옆에 붙어 있어 나중에 늘릴 수 없습니다.
    • 무엇이든 잠시 둡니다: 데이터셋 버퍼, 체크포인트, 내려 둔 가중치와 KV 캐시를 모두 담습니다.
    4.6

    부재 시 문제

    Host Memory가 모자란다고 가정해 보면, 이런 문제가 생깁니다.

    • DataLoader 워커가 메모리가 모자라 죽거나 느려지고, 그동안 GPU는 기다립니다.
    • 체크포인트를 저장하다가 실패합니다.
    • 오프로딩과 KV 캐시 확장을 할 수 없어, 같은 GPU로 다룰 수 있는 모델과 문맥 길이가 줄어듭니다.
    Q. GPU 메모리는 남는데 학습 Pod가 OOMKilled로 죽어요. 왜 그런가요?

    GPU 메모리가 아니라 Host Memory, 즉 Pod의 메모리 한도를 넘은 것입니다. DataLoader 워커 수, Pinned 버퍼, 체크포인트를 저장할 때 잠깐 늘어나는 메모리를 함께 따져야 합니다. 워커들이 함께 쓰는 공유 메모리 /dev/shm이 모자라면 OOMKilled 대신 bus error로 나타나기도 합니다. 메모리 한도는 16회차에서 다룹니다.

    4.7

    단점

    • GPU에서 보면 멉니다: DDR5 자체는 소켓 하나에 수백 GB/s지만, GPU까지 오는 길은 PCIe Gen5 x16 한 방향 약 64GB/s입니다. 병목은 메모리가 아니라 길입니다.
    • 어느 소켓 메모리냐에 따라 다릅니다: CPU가 두 개인 서버에서는 GPU와 같은 소켓의 메모리를 써야 빠릅니다. 8회차에서 봅니다.
    • Pinned는 마음껏 못 씁니다: 너무 많이 고정하면 시스템 전체가 느려집니다. 6회차 4.7에서 봤습니다.
    4.8

    단점 극복을 위한 대안 기술

    1. Pinned Memory와 비동기 전송

    • 뜻: 보낼 데이터를 Pinned 버퍼에 두고, 계산과 겹쳐 보냅니다. 6회차 4장에서 봤습니다.
    • 해결하는 단점: 느린 길을 계산 뒤로 감춥니다.

    2. GPUDirect Storage

    • 뜻: 스토리지에서 GPU로 Host Memory를 거치지 않고 바로 보냅니다. 9회차에서 다룹니다.
    • 해결하는 단점: Host Memory를 거치는 단계 자체를 없앱니다.

    3. CXL 메모리 확장

    • 뜻: 로 메모리 장치를 붙여, CPU 메모리 용량을 늘립니다.
    • 해결하는 단점: 메모리 채널 수에 묶인 용량 한계를 넘깁니다.

    4. 하드웨어로 묶인 CPU 메모리

    • 뜻: Grace와 Vera처럼 CPU와 GPU를 NVLink-C2C로 묶어, GPU가 CPU 메모리를 빠르게 바로 씁니다.
    • 해결하는 단점: GPU에서 멀다는 문제를 풉니다.
    4.9

    대안과의 비교

    층용량GPU에서 본 대역폭 (대략)용도

    4.10

    최신 트렌드

    1. KV 캐시를 Host Memory로 내립니다

    • 긴 문맥과 많은 사용자를 받는 추론에서, 를 VRAM에서 Host Memory로, 다시 SSD로 내려 두는 기능이 추론 엔진의 핵심이 됐습니다.
    • NVIDIA Dynamo 문서는 KV Block Manager, 줄여서 KVBM과 LMCache 같은 방식으로 KV 캐시를 CPU 메모리와 디스크로 넓힌다고 설명합니다. vLLM에는 KV 블록을 Pinned CPU 메모리로 내리는 OffloadingConnector가 들어 있습니다.
    • 2026년 NVIDIA는 KV 캐시 전용 저장 층인 BlueField-4 기반 Inference Context Memory Storage도 내놓았습니다. 6회차 4.10에서 본 내용입니다.

    2. CPU 쪽 메모리 길도 넓어집니다

    • 2025년 11월 CXL 컨소시엄은 CXL 4.0 규격을 공개했습니다. 속도를 64GT/s에서 128GT/s로 두 배 올렸습니다. PCIe 7.0과 같은 속도입니다.
    • 2026년 7월 출시된 AMD EPYC Venice는 소켓 하나에 DDR5 16채널, 약 1.6TB/s의 메모리 대역폭을 내세웠습니다.
    꼭 알아 둘 것Host Memory는 이제 VRAM의 다음 층입니다. VRAM, Host Memory, SSD를 하나의 계층으로 보고 데이터를 옮기는 설계가 늘고 있습니다.

    여기까지가 CPU와 GPU를 잇는 길, PCIe와 그 끝의 Host Memory였습니다. 다음 8회차에서는 이 길 위에서 데이터가 실제로 어떻게 움직이는지 봅니다. CPU 소켓마다 메모리까지의 거리가 다른 NUMA, CPU 대신 장치가 메모리를 직접 읽는 DMA, GPU 메모리를 CPU 주소에 여는 창구인 BAR, 그리고 CPU 병목입니다. GPU끼리 PCIe를 거치지 않고 잇는 NVLink와 NVSwitch는 9회차에서 다룹니다.
